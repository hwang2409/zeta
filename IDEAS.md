# Zeta experiment ledger

Each candidate needs a baseline, a changed arm, and a real workflow check before
merge. A green unit suite alone is not evidence of better agent outcomes.

| Idea | Status | Evidence and next gate |
| --- | --- | --- |
| Small, repeatable real-workflow evals for Zeta's normal tools and model team | PR #222 merged; needs broader corpus | `evals/run.py` grades five live Luna workflows in fresh directories and reports artifacts separately from completion. The earlier 5/5 artifact, 2/5 completion run exposed tool/turn overhead that unit tests missed. Expand to real repos and repeat before treating percentages as stable. |
| Skip `todo` for one edit plus verification | PR #223 merged | On the one-edit task, unchanged identity completed 3/8 and the exact appended rule completed 8/8; artifacts were 16/16. Both arms completed 8/8 on four other tasks (two repeats each). The changed packaged identity in a fresh `ZETA_HOME` completed 16/16 across all five tasks; the updated local user identity completed another 4/4 one-edit runs. Existing user-edited identities do not update automatically. |
| Cache reuse on real workflows | Measured; no client prefix churn found | Opt-in trace across 18 Luna completions in three short workflows: 47,104 cached of 65,060 input tokens (72.4%). A separate 18-completion Opus 5.5 repair of Zeta's file-descriptor bug read 364,362 of 398,027 input tokens from cache (91.5%). Each of its 17 subsequent completions retained the prior message prefix and the same 16 tools, with no compaction; the longest inter-completion gap was 266 seconds. A clean Anthropic session resume 395 seconds after the preceding request read 5,298 cached tokens, wrote 23, and used 4 uncached (99.5%), confirming the selected 1-hour TTL works across a pause. An earlier resume missed because the tool schema changed during that interval. [OpenAI's caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) explains that newly appended input remains uncached even on a prefix hit. Do not pad prompts to inflate hit rate. |
| Give child cache traces parent-qualified IDs | PR #233 merged | Two separate headless team runs both logged their first child as `session_id: "1"`, making per-child aggregation ambiguous across sessions. Child agents already carry a canonical parent-qualified `agent_instance_id`, so the trace now uses it while roots retain their session ID. A live Opus/Luna/Sol run recorded root `db85…` and children `db85…:1`, `:2`, and `:3`; the full local suite passed 3,306 tests (7 skipped), and Ubuntu/macOS CI passed. This changes diagnostics only. |
| Make workflow-eval scoring reject malformed event fields | Local regression and live workflows passed; PR pending | Current `evals/run.py` raises `KeyError` when syntactically valid JSONL contains a `tool_call` without a name or a `usage` event without an object payload. The candidate returns a numbered run error instead; five injected cases plus the existing invalid-JSONL case pass. Live Luna count-and-write (1 tool call) and inventory-chain (10 tool calls) both passed artifacts and completion; Ruff is clean. Gate: Ubuntu/macOS CI before merge. |
| Reduce turns spent on bookkeeping and child-agent coordination | Investigating; one real-repo pair was inconclusive | In the 5-task packaged-prompt trial, three correct artifacts still hit their turn caps. On a disposable checkout of pre-fix Zeta, Luna repaired the real file-descriptor race in both 18-turn arms. The default arm used `todo` and a child agent, passed 87 file-tool tests but failed Ruff; a no-bookkeeping/no-delegation rule avoided those calls and passed tests plus Ruff. Both hit the turn cap without a final response. A separate live inventory task completed in 12 tool calls, including four `todo` calls. One pair is not evidence to merge the rule; test more tasks and use a less restrictive cap. |
| Keep headless JSONL free of TUI background notices | PR #226 merged | A shell-only browser baseline produced a non-JSON stdout line when a background task exited, breaking `jq` and then raising `BrokenPipeError`. A focused test reproduced the ANSI notice in stdout before the fix and passed afterward. A live Luna task using `run_background` and `task_output` then produced a strictly parseable JSON stream. Headless now detaches background, hook, and wake callbacks before the turn; Ubuntu/macOS CI passed. |
| Avoid unhandled submission shutdown tasks | PR #228 merged | The 3,303-test full suite passed but printed `SubmissionPipeline._consume` task exceptions after weakly-referenced hosts disappeared. Closing the owning app in command and plan-mode tests removed them. The final 3,305-test full suite passed without unhandled task exceptions (one expected torn-file warning); Ubuntu/macOS CI passed. |
| Keep optional browser tests optional when Chromium is absent | PR #228 merged | Playwright's Python package alone does not install browser binaries. The live browser test failed when the package was present but Chromium was absent. It now skips only the missing-executable error, still fails other browser errors, and passes with the disposable Chromium runtime; Ubuntu/macOS CI passed. |
| Fail workflow evals on malformed headless JSONL | PR #229 merged | The evaluator previously ignored invalid output lines, so a valid final message plus the TUI notice fixed in #226 could be scored as complete. An injected ANSI notice now yields an invalid-JSONL run error. The changed evaluator passed live Luna count-and-write (1 tool call) and inventory-chain (12 tool calls) tasks with both artifacts and completion true; Ubuntu/macOS CI passed. |
| Give each file descriptor exactly one close owner | PR #227 merged | Ubuntu CI for #226 exposed `Bad file descriptor` in the pre-existing symlink-race test. `read`, `write`, and `edit` wrapped `open_target`'s descriptor with default `os.fdopen(closefd=True)`, then `open_target` closed it again; a concurrent open could reuse that number between closes. The wrappers now borrow it with `closefd=False`. All 87 file-tool tests pass locally, the race test passed 30 consecutive runs, and Ubuntu/macOS CI plus a 3,304-test local run passed. |
| One generic interactive `browser` tool, with Jev selecting elements from a bounded page snapshot | PR #225 merged | Disposable Chromium passed a local delayed-click and duplicate-element test. On live TodoMVC, the first role/name-only version hit its turn cap; zero-based index yielded two verified completions. Without a browser tool or runtime hint, shell hit 12 turns. With the same explicit Playwright runtime hint, shell succeeded in one call (~10s) and the batched browser tool in three (~11s): this is a discoverability/restricted-action gain, **not** a latency win over an informed shell. On a live dropdown, Luna browser selected Option 2 in two calls and Opus 5.5 in three; shell-only Luna without a hint could not act on the UI. The tool stays opt-in and approval-gated. Next: broader workflows before Jev routing. Jev's 36/60 routed vs 26/60 stock result remains an **offline fake-page** matrix, not live evidence. Source: private `hwang2409/jev/harness/evals/RESULTS.md`. |
| Scope browser actions to one named container | PR #230 merged | A shuffled 500-product page placed Product 100 at button index 356, beyond the 10k-character snapshot cap (the target was around character 46,586). With browser-only Luna and an 8-turn cap, the unchanged tool located the article but could not act on its repeated button and hit the cap; the scoped role/name action opened, clicked, and verified in two calls. On Product 387, Opus 5.5 succeeded via a seven-call keyboard workaround on the old tool versus two calls with scope. A public TodoMVC add/toggle/verify workflow also completed with the changed tool in eight calls. The full local suite passed 3,306 tests with the disposable browser, and Ubuntu/macOS CI passed. A predictable-sequence page was discarded as a weak baseline after Luna inferred the hidden index. |
| Accept common browser key spellings | PR #231 merged | In public TodoMVC, Luna naturally sent `ENTER`, which Playwright rejected before the model retried with `Enter`. In a matched live task explicitly using uppercase `ENTER`, the old tool rejected the key and Luna recovered in four browser calls; the Enter-tolerant tool succeeded in a two-call batch. A local browser-page test confirms the uppercase alias; Ubuntu/macOS CI passed. Other spellings (`CTRL+f`, `END`) remain unmodified until a useful live action needs them. |
| Keep headless cross-model agents alive until their result returns | PR #232 merged | On a disposable pre-fix Zeta checkout, a headless Opus orchestrator launched the configured Luna implement agent in the background, returned “I'll wait for the completion announcement,” and exited with no patch or Sol review. The changed one-shot path runs child agents synchronously: the same prompt produced a Luna patch, Sol review with no findings, and an Opus final. Independent file-tool/sandbox checks passed 106 tests (1 skipped), Ruff passed, the full local suite passed 3,306 tests (7 skipped), and Ubuntu/macOS CI passed. The implement child hit its 25-turn cap, so that budget needs separate study. |
| Give substantial implementation children enough turns | Investigating; matched pair inconclusive | On the file-descriptor repair, default-budget Luna reached its 25-turn cap after 35 tool calls, leaving a useful patch but no summary; Opus recovered. A fresh checkout with `max_turns=40` passed to the implement agent produced a Luna summary, but Luna used only 25 completions, so the higher cap is not proven causal. Sol then caught a false-positive regression test, Opus repaired it, and the full suite passed 3,303 tests (7 skipped); an independent 106-test file-tool/sandbox slice and Ruff passed. Test more tasks before changing the default. |
| Compare Opus-only with Opus/Luna/Sol on real repairs | Investigating; one matched task, no routing change | On the same pre-#229 Zeta checkout and malformed-JSONL repair, Opus-only used 13 completions and passed its 3,308-test suite, but an unrequested malformed `tool_call` case still raised `KeyError`. The team used 9 Opus, 30 Luna, and 8 Sol completions; Sol found blank-line acceptance and the malformed-call crash, Luna repaired both, and the resulting artifact passed 3,309 tests plus the adversarial case. Review found real defects here, but the team used far more turns; repeat on diverse tasks and compare cost per verified outcome before changing routing. |
| Disposable computer for each agent session | Blocked for cloud validation | [Muse](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/) uses a dedicated browser-equipped VM with separate approval controls. Mock locally first; local Docker is installed but its daemon is unavailable. A real remote VM needs an account/provider choice and spending limit. No cloud deployment yet. |
| Agent-to-agent handoff across users | Researching | [Instinct's founder](https://x.com/noahrshinn/status/2097794967574028448) describes trusted-person connections, agent-to-agent plan coordination, and end-to-end file transfer, but no public wire protocol was found. The intriguing part is identity, consent, and an auditable handoff, not another chat tool. Prototype only between two local Zeta sessions before involving another person. |

Evaluation reference: [Harbor](https://github.com/harbor-framework/harbor) runs
agents against containerized, verifiable tasks. Zeta should first use a tiny
local corpus; integrate a full Harbor adapter only if that corpus shows value.
