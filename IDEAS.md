# Zeta experiment ledger

Each candidate needs a baseline, a changed arm, and a real workflow check before
merge. A green unit suite alone is not evidence of better agent outcomes.

| Cache reuse on real workflows | Measured; no client prefix churn found | Opt-in trace across 18 Luna completions in three short workflows: 47,104 cached of 65,060 input tokens (72.4%). A separate 18-completion Opus 5.5 repair of Zeta's file-descriptor bug read 364,362 of 398,027 input tokens from cache (91.5%). Each of its 17 subsequent completions retained the prior message prefix and the same 16 tools, with no compaction; the longest inter-completion gap was 266 seconds. A clean Anthropic session resume 395 seconds after the preceding request read 5,298 cached tokens, wrote 23, and used 4 uncached (99.5%), confirming the selected 1-hour TTL works across a pause. An earlier resume missed because the tool schema changed during that interval. [OpenAI's caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) explains that newly appended input remains uncached even on a prefix hit. A traced generic team repair kept the full prior-message prefix and the same tools within all six sessions, yet Luna had occasional zero-read completions; aggregate child cache reads were 68.0% versus Opus 90.6%. That is not evidence of client prefix churn. Do not pad prompts to inflate hit rate. |
